# tidy — 정제와 완료 판정

부르는 때: "백로그 정리해줘", "이 기능 다 된 것 같아", 주기적 점검.

두 가지 일을 한다. **백로그를 정제하는 일**과 **항목을 닫아도 되는지 판정하는
일**이다. 요청에 따라 한쪽만 할 수도 있다.

## A. 정제

백로그 전체를 훑는 유일한 갈래다. 로컬이면 `local-backlog.md` 의 조회 명령을 쓴다.

### 1. 고아 탐지

부모가 없거나, `parent` 가 가리키는 항목이 존재하지 않는 Story 를 찾는다.

발견하면 **지우지 말고 부모를 찾아 연결한다.** 부모가 정말 없으면 새
Epic 이 필요한 신호일 수 있다.

### 1-1. 트랙 어긋남 점검

발견과 전달이 섞이면 백로그 상태가 실제와 어긋난다. 셋을 본다.

| 증상 | 처리 |
|---|---|
| 전달 에픽이 열려 있는데 서술서·계약이 없다 | 발견 에픽으로 되돌리거나, 앞에 발견 에픽을 세운다 |
| Story 의 부모가 발견 에픽이다 | 전달 에픽으로 옮긴다 |
| 발견 에픽이 닫혔는데 "남은 질문"이 남아 있다 | 답이 났으면 서술서로 옮기고 지운다. 안 났으면 에픽을 다시 연다 |

### 2. 방치된 하단 점검

오래 손대지 않은 하단 항목을 모은다. 사용자에게 **폐기를 제안한다.**

제안이지 실행이 아니다. 항목을 지우는 것은 되돌리기 어려우므로 목록을 보여주고
확인을 받는다. 판단 근거(마지막 수정 시점, 관련 Epic 이 이미 닫힘 등)를 함께 적는다.

### 3. 우선순위 재정렬

**위는 곱게, 아래는 거칠게.**

| 구획 | 상태 |
|---|---|
| 진행 중 | 인수 조건이 완비되어 있다 |
| 다음 | 인수 조건이 있고 크기가 한 이터레이션 안이다 |
| 나중 | 제목만 있어도 된다. 상세화하지 않는다 |

**하단을 다듬으려는 충동을 막는다.** 요구사항은 바뀌고, 지금 곱게 다듬은 하단은
버려질 가능성이 높다.

위로 올라온 항목은 그때 상세화한다. 로컬이면 이 시점에 항목 파일을 만든다.

### 4. 닫힌 항목의 서술서 갱신 누락 점검

서술서를 유지하는 프로젝트라면, 닫힌 Story 중 서술서에 반영되지 않은 것을 찾는다.
DoD 의 일부인데 자주 빠뜨리는 항목이다.

## B. 완료 판정

"이 기능 다 된 것 같아"에 **바로 동의하지 않는다.** 대조부터 한다.

### 1. 인수 조건 체크리스트 대조

항목의 인수 조건을 하나씩 실제 동작과 맞춰본다. 체크박스가 비어 있는 것뿐
아니라, **체크되어 있지만 실제로는 확인되지 않은 것**도 찾는다.

### 2. 각 조건이 어느 층위로 커버됐는지 확인

| 조건의 성격 | 검증 층위 |
|---|---|
| 로직 | 단위 테스트 |
| 비즈니스 규칙 | API / 통합 테스트 |
| UI 표시, 전 구간 관통 | E2E |

**자동화되지 않은 조건도 닫을 수 있다.** 다만 수동으로 확인한 뒤에 닫는다.
100% 자동화가 목표가 아니다.

**단위 테스트 이름에 인수 조건이 붙어 있으면 의심한다.** 경로 전체를 지나는
테스트에만 Story 키와 인수 조건을 붙이는 것이 규칙이다. 함수 하나의 테스트가
인수 조건 이름을 갖고 있으면, 그 조건이 커버됐다는 주장이 거짓일 수 있다.

### 3. DoD 충족 시에만 닫기를 권고한다

- 인수 조건 전부 확인
- 서술서를 유지하는 프로젝트라면 관련 서술서 갱신

**닫는 것은 사용자가 정한다.** 미충족 항목이 있으면 무엇이 남았는지 알리고,
그래도 닫겠다면 따른다.

## 흔한 실수

| 실수 | 이유 |
|---|---|
| 고아 스토리를 지운다 | 부모를 찾아 연결하는 게 먼저다. 지우면 맥락이 사라진다 |
| 하단까지 인수 조건을 채운다 | 버려질 항목을 다듬는 일이다 |
| "다 된 것 같아"에 바로 동의한다 | 인수 조건 대조가 이 갈래의 존재 이유다 |
| 자동화 안 된 조건이 있다고 안 닫는다 | 수동 확인 후 닫는 것이 원칙이다 |
| 폐기를 확인 없이 실행한다 | 되돌리기 어렵다. 목록을 보여주고 확인받는다 |
